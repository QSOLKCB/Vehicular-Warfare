# FX gate beacon

On the Breakwater Reach or workshop briefing, check **FX gate beacon** to add a rotating marker above your crew’s capture gate. Its hollow lip and hanging pointer mark the centre of the circle outlined by the original ground lamps. Amber marks the relay-locked gate, green marks the open gate and blue marks the captured gate. The mission HUD continues to describe each stage in text. The marker uses normal world depth so a hill or vehicle can hide it.

The ground lamps are the default. Press **G** during a mixed battle to toggle the experiment, or change the checkbox while paused. In the workshop replay viewer, the same control sits beside the playback controls and redraws a stationary frame at the selected tick. The preference belongs to this browser origin. Gate position, relay health and capture status come from the accepted mission. The checkbox and G key update the view preference. ## Geometry and lifetime

`CombinedView(canvas, world, {fx: true})` selects the experiment explicitly. Passing `false` selects the ground lamps alone. Omit `fx` to follow the UI. Both paths retain the original field mesh, lamp geometry, vehicle models, shadows, effects, chart and camera.

`FxGateBeacon` owns a static Q16.16 triangle template. At each new phase the program gives `FxGraphicsPipe` a row-major, fixed-point rotation and translation copied from the gate location. It appends 20 coloured triangles, consuming the interleaved Float32 XYZ/RGB output immediately for one WebGL1 mesh update. The rotation advances one of 48 phases every six accepted ticks. A change in gate state also refreshes the palette. Between updates the renderer can draw the existing GPU buffer. Seeking to an earlier tick reproduces the same geometry. The test compares all vertex coordinates to an independent floating-point calculation with a 0.00005 game-metre tolerance, including transforms near the map edges. [Geometry and restoration tests](../test/fx-gate.test.js)

The optional layer adds 60 vertices and one draw call whenever enabled. A fresh reference view creates zero beacon buffers. The first enabled frame creates one mesh with a 1,440-byte geometry buffer and 2,459 bytes of retained CPU typed-array data, including source coordinates, colours, the application and pipe transforms, and the pipe’s scratch storage. Toggling off suppresses the draw. Toggling back on reuses the same storage. Pausing, restarting or leaving the station disposes the renderer and releases its meshes. Stationary replays release the renderer after each requested redraw.

`lastDraw.fxEnabled`, `fxUpdated`, `fxPrepMs`, `fxVertices` and `fxRetainedBytes` expose the draw state, upload decision, CPU geometry preparation time, submitted vertices and live CPU storage. Geometry timing excludes the GL upload and submission. The byte count covers owned typed-array payloads. The upstream transform validator creates a private matrix copy and property descriptors at each preparation, and `view()` creates a short-lived upload view. JS object overhead, driver allocations and garbage collection depend on runtime. [Pinned public engine contracts](ENGINE_BASELINE.md)
